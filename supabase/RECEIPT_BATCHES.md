## Frontend batch scan preparation

QR generation and receipt navigation remain unchanged. In Scan code mode, the shared product selector classifies the full input before matching SKUs. It accepts current-origin HTTP(S) `/transfers?batch=<id>` URLs and root-relative equivalents, with exactly one nonempty batch parameter and no extra parameters, credentials, or fragment. Other origins (including old deployment domains) require an explicit future trust-policy decision. IDs are decoded using the URL API, not interpreted as SKUs. Malformed batch links display `Invalid batch QR.` Normal SKU scans and the Enter SKU tab retain their existing matching behavior.

No caller currently configures a batch resolver. A recognized batch QR displays `Batch QR lookup is not available yet. Enter the product SKU or use Select products.` It does not select a product, navigate, fetch data, or fall back to SKU matching. This preparation adds no network requests, RPC assumptions, or reads of `inventory_movements`.

Future integration must supply both `resolveBatch(batchId, { signal })`, returning `{ productId }` or `null`, and a stable `getProductId(option)` accessor to `ProductSelectionModes`. Keep these function references stable during a request. The selector prevents concurrent submissions, cancels/ignores stale requests, rechecks current eligible options, rejects missing/ambiguous matches, and retains the existing `onAdd` validation. Camera lookup failures are retryable with a two-second delay; manual submissions can be retried immediately. Supply Chain transaction-line IDs must not be mistaken for product IDs.

The backend prerequisite is an authorized, read-only lookup exposing only `batchId -> productId`. It must validate authentication and effective module/delegation permissions server-side, resolve exactly one external receipt item, reject ambiguity, and disclose no receipt costs, invoices, supplier or financial details. Inspect deployed authorization policies before implementing that endpoint. Do not enable this by loading full receipt records or broadening receipt-view permissions. A batch lookup identifies a product/variant; it does not allocate or deplete a particular batch. No backend resolver or database change is included in this frontend preparation.
